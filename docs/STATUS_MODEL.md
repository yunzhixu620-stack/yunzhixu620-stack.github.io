# 产品状态标准

状态用于描述当前公开交付能力，不表示项目的重要程度，也不根据页面视觉完成度判断。

## 可用产品

核心任务可以真实完成；页面公开承诺与实际能力基本一致；失败时有明确提示或恢复路径。

不代表：已经商业化、支持大规模并发、完成全部合规程序或拥有大量用户。

## MVP

核心闭环已经存在并可以验证，但至少还有一项重要条件未完成，例如多人协作、真实服务接入、外部验证、内容深度或长期稳定性。

展示时必须明确写出缺少的条件。

## 交互原型

主要用于展示产品流程、界面和业务判断。即使按钮可以点击，也不能把模拟数据、前端校验或概念接口描述为真实生产能力。

## 实验

用于验证某种交互、技术或内容表达。可能依赖临时服务和私人场景，不承诺稳定、维护周期或完整用户流程。

## 已归档

不再作为当前主产品维护，仅保留产品演进、技术复盘或兼容入口。页面必须指向当前替代产品，安全问题除外不再增加功能。

## 状态升级条件

- 交互原型 → MVP：核心流程接入真实数据或确定性服务，并能完整完成一次任务。
- 实验 → MVP：确定目标用户、主要任务、输入输出和失败边界，完成至少一轮真实用户验证。
- MVP → 可用产品：核心任务稳定、公开承诺准确、数据可恢复、异常可解释，并完成与风险相称的测试。
- 任意状态 → 已归档：已有明确替代产品，或继续维护会造成入口和定位混乱。

每次升级必须同时更新 `projects.js`、根目录 `README.md` 和对应项目 README。
